[세션 1] FPS 14 원인 확인 (VR 모드)
────────────────────────────────────────────────────────────────

## 증상
  VR 모드에서 FPS가 14까지 떨어짐. 오디오 관련 코드 revert 후에도 지속.

## 원인 분석
  - 오디오 코드 작성 중 XR Input subsystem만 Start하는 코드가 있었음
    → revert했으나 Unity Editor XR 런타임 상태가 오염됨
  - Main.unity 직렬화에 stale 필드 잔존:
      _reacquireXrWhileGated: 0  (기본값 1에서 변경됨)
      _keepDesktopAudioInVR: 1   (오디오 코드 잔재)
  - 코드 자체는 HEAD와 동일하게 복구됨 — 에디터 상태 문제

## 해결 방법 (사용자 수동)
  Unity Editor 완전 재시작 + Inspector에서 _reacquireXrWhileGated = true 수동 확인
  → 코드 변경 불필요, 에디터 재시작으로 해소

[세션 4] 캐릭터·오브제 로드 전 게임 시작 버그 수정
────────────────────────────────────────────────────────────────

## 파일
  Scripts/Object/GeneratedObjectSpawner.cs
  Scripts/Managers/GameFlowManager.cs

## 증상
  Server 모드 빌드에서 에셋이 로드되기 전에 게임이 시작되고
  이전 세션의 캐릭터·오브제가 표시됨. 에디터에서는 정상.

## 원인
  GeneratedObjectSpawner.Spawn()에 완료 콜백이 없어 GameFlowManager가
  GLB 로드 완료를 기다리지 않고 ReadyToEnter()를 즉시 호출함.

## 수정 — GeneratedObjectSpawner.cs
  Spawn() 시그니처에 onReady 콜백 추가:
    public void Spawn(ObjectAssetData data, System.Action<GameObject> onReady = null)
  - model_url 없음(Mock) → SpawnMock() 후 onReady?.Invoke() 동기 호출
  - model_url 있음(Server) → SpawnFromServerCoroutine() 비동기, 완료 후 onReady?.Invoke()
    private IEnumerator SpawnFromServerCoroutine(ObjectAssetData data, Action<GameObject> onReady)
    {
        var task = SpawnFromServerAsync(data);
        yield return new WaitUntil(() => task.IsCompleted);
        onReady?.Invoke(_spawnedObject);
    }

## 수정 — GameFlowManager.cs : TryReadyToEnter 게이트 패턴
  새 필드:
    private bool _guideSpawnReady;
    private bool _objectSpawnReady;

  SpawnSession() 진입 시:
    _guideSpawnReady  = false;
    _objectSpawnReady = (_objectSpawner == null || session.assets?.@object == null);

  오브제 스폰에 콜백 추가:
    _objectSpawner.Spawn(session.assets.@object, objectGO => {
        _spawnedObjectGO  = objectGO;
        _objectSpawnReady = true;
        TryReadyToEnter();
    });

  가이드 스폰 콜백에서:
    _guideSpawnReady = true;
    TryReadyToEnter();

  새 메서드:
    private void TryReadyToEnter()
    {
        if (_guideSpawnReady && _objectSpawnReady)
            ReadyToEnter();
    }

  효과: 가이드 NPC + 오브제 양쪽 모두 스폰 완료 시에만 게임 진행

[세션 5] 스테일 세션 버그 수정
────────────────────────────────────────────────────────────────

## 파일
  apps/backend/api/routers/sessions.py
  Scripts/Managers/SessionManager.cs

## 증상
  Unity 강제 종료 후 재시작 시, 다음 세션 대신 이전 세션의 캐릭터·오브제가 표시됨.

## 근본 원인
  1. Unity 강제 종료 시 AdvanceQueue 미호출 → Redis lego:active_session 키 잔존
  2. /sessions/active 엔드포인트가 "runtime" 상태 세션도 그대로 반환:
       if active_session.status not in ("cancelled", "completed"):
           return {"session_id": active_id}   ← "runtime"도 반환 (버그)

## 수정 — sessions.py : /sessions/active 엔드포인트
  "runtime" = Unity 강제 종료로 남은 스테일 세션으로 판단, 자동 advance:
    if active_session.status not in ("cancelled", "completed", "runtime"):
        return {"session_id": active_id}   # 아직 시작 안 된 유효 세션
    # runtime / cancelled / completed → 스테일 처리
    if active_session.status == "runtime":
        active_session.status = "completed"
        db.commit()
    uq.move_active_to_history(active_id)
    # 다음 큐 팝
    session_id = uq.pop_unity_for_runtime()
    ...

  근거:
  - FetchActiveSession은 Start(첫 실행) 또는 AdvanceQueue 이후에만 호출됨
  - 두 경우 모두 "runtime" 세션이 남아있으면 반드시 스테일임
  - AdvanceQueue 정상 호출 시 이미 lego:active_session 삭제됨

## 수정 — SessionManager.cs : OnApplicationQuit() 추가
  private void OnApplicationQuit()
  {
      // best-effort: 완료 보장 없음 — 실패 시 서버 /sessions/active가 자동 advance
      if (dataSourceMode == DataSourceMode.Server
          && _apiClient != null
          && !string.IsNullOrEmpty(sessionId))
      {
          StartCoroutine(_apiClient.AdvanceQueue(_ => { }));
      }
  }

  역할: 정상 종료 시 서버에 advance 신호 전달. 강제 종료 시엔 서버 수정이 주 방어선.
