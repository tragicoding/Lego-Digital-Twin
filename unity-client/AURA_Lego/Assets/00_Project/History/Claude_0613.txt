[세션 2] 런타임 성능 최적화 — 공통 유틸 신설
────────────────────────────────────────────────────────────────

## 방침 (사용자 결정)
  메시 decimation 라이브러리 도입 대신, GTX1060급에서 실제 지배 비용인
  "그림자 캐스팅"과 "스키닝 품질", "상시 물리 시뮬레이션"을 낮춰 FPS 확보.
  메시(폴리곤)는 원본 유지. Mock(저폴리)·Server(고폴리) 동일 호출 —
  저폴리엔 영향 미미, 고폴리에서 큰 이득.

## 신규 파일 1: Scripts/Core/RuntimeOptimizer.cs (static)
  Optimize(GameObject go): 하위 모든 Renderer/SkinnedMeshRenderer에 적용
    - shadowCastingMode = Off          (그림자 캐스팅 제거 — GPU 핵심 절감)
    - receiveShadows                    (옵션, 기본 유지)
    - SkinnedMeshRenderer.quality = Bone2  (본 4→2, 스키닝 비용 절감)
    - skinnedMotionVectors = false
  전시 기본값은 static 필드로 한 곳에서 조정:
    disableShadowCasting=true / disableShadowReceiving=false /
    limitSkinQuality=true / skinQuality=Bone2 / disableSkinnedMotionVectors=true
  여러 번 호출해도 안전(idempotent).

## 신규 파일 2: Scripts/Object/PhysicsSettler.cs (MonoBehaviour)
  낙하한 전시 오브제가 바닥에 안착하면 Rigidbody를 kinematic으로 전환해
  상시 물리(Continuous 충돌검사 포함) 비용을 제거하고 스스로 컴포넌트 제거.
    - settleTime=0.5s 동안 linearVelocity < 0.05 유지 → 안착 판정
    - maxWaitTime=10s 안전망(무조건 안착)
    - kinematic 전환 전 collisionDetectionMode=Discrete (Continuous+kinematic 경고 방지)
  ※ Unity 6 API(linearVelocity) 사용.

## 증상
  Play 약 3초 후 에디터·플레이가 함께 얼어붙음. 동시에 콘솔에:
    Unable to perform online search:
    Request [GET https://packages.unity.com/-/api/search] failed with status code [502]
    UnityEditor.EditorApplication:Internal_CallUpdateFunctions ()

## 원인 (게임 코드 무관)
  packages.unity.com/-/api/search 는 Editor 전용 Package Manager API.
  레지스트리를 주기적으로 폴링하는 패키지들이 서버 502 응답에 메인 스레드를
  동기 블로킹 → 에디터·플레이가 같이 멈춤. 런타임 스크립트는 이 요청을 못 보냄.

## 해결 — 불필요 폴링 패키지 5개 제거 (Packages/manifest.json)
  com.unity.ads (4.4.2)              광고
  com.unity.analytics (3.8.1)        분석
  com.unity.purchasing (4.12.2)      인앱결제
  com.unity.learn.iet-framework (5.0.1)  인터랙티브 튜토리얼
  com.unity.multiplayer.center (1.0.0)   멀티플레이 설정 허브

## 서버 모드 영향 점검 (코드 검색으로 입증)
  Assets/00_Project 전체에서 Advertisement/Purchasing/Analytics/Tutorials/
  Multiplayer.Center 사용처 0건. 서버 통신은 아래로만 동작 → 전부 유지됨:

  → Mock·Server 어느 모드에도 영향 없음. 제거 후 멈춤 사라짐(사용자 확인).

[세션 1] 원인 분석 — 콜라이더가 아닌 낙하·동결이 문제
────────────────────────────────────────────────────────────────

## 파묻힘 (이전 창작물 일부)
  씬에서 BoxCollider 크기는 메시와 정확히 일치함을 확인 → 콜라이더 사이즈 문제 아님.
  진짜 원인: objectDropHeight=15 + objectSpawnScale=12 큰 오브제가 ~17m/s로 착지 →
  한 프레임에 깊게 관통 → 솔버가 밀어내는 도중 PhysicsSettler가 velocity<0.05·0.5초
  조건으로 kinematic 동결 → 관통한 상태 그대로 굳어 파묻힘. (관통 깊이가 메시·자세별로
  달라 "몇몇 개만" 묻힘)

## 공중에 뜸 (나의 창작물)
  GeneratedObjectSpawner는 ObjectSpawnPoint.position.y를 바닥으로 사용 →
  spawnPoint Y가 높게 설정돼 있어 그 높이에 떠서 안착.

[세션 2] 낙하 제거 — RuntimePhysicsUtil.PlaceOnGround 신설
────────────────────────────────────────────────────────────────

## 수정: Scripts/Object/RuntimePhysicsUtil.cs (전면 교체)
  - SetupSimplePhysics(Rigidbody+중력+낙하) 제거 → PlaceOnGround(go, fallbackGroundY) 신설
  - 동작:
      ① footprint 중심에서 아래로 Ground 레이어(인덱스 6) 레이캐스트 → 실제 바닥 Y
         (QueryTriggerInteraction.Ignore, 못 맞히면 fallbackGroundY 폴백)
      ② 메시 바닥(bounds.min.y)이 바닥 Y에 닿도록 Y만 보정 (물리 낙하 없음)
      ③ 기존 검증된 방식으로 루트 BoxCollider 재계산 (InverseTransform — 씬에서 일치 확인)
  - 프리팹에 Rigidbody 있으면 isKinematic=true로 낙하 차단
  → spawnPoint Y가 높아도 항상 바닥에 앉음. 회전·스케일 무관.

## Ground 레이어 근거
  TagManager: Ground = layer 6. Main.unity에서 124개 오브젝트가 Ground 레이어 사용

[추가 작업 / 트러블슈팅] TMP 폰트 저장소 비대화 정리 (Static/Dynamic·atlas)
날짜: 2026-06-13
브랜치: feature/unity
================================================================

주제: 대기화면 텍스트 추가로 Pretendard-ExtraBold SDF가 55MB로 커지며 push 시
      GitHub 50MB 경고 발생. 폰트 저장소 용량 정리 과정에서 겪은 시행착오와 결론.

────────────────────────────────────────────────────────────────
[배경·원인]
────────────────────────────────────────────────────────────────
  - Pretendard SDF 폰트가 8종 × ~38MB + Noto 38MB ≈ 390MB로 저장소의 큰 덩어리.
  - 용량의 정체는 글리프가 아니라 4096×4096 atlas 텍스처가 .asset에 직렬화된 것.
  - TMP Atlas Population Mode: 0=Static(런타임 글리프 생성 X), 1=Dynamic(OTF에서 생성).

────────────────────────────────────────────────────────────────
[시행착오 — 하지 말 것]
────────────────────────────────────────────────────────────────
  ① Clear Dynamic Data 후 Static으로 전환 → 글자 전부 □로 깨짐.
     원인: Static은 atlas에 구운 글자만 표시하는데 Clear로 비웠으니 빈 atlas.
     → 복구: git checkout으로 커밋된 정상본 복원(소스 OTF GUID 살아있어 가능).
  ② 인스펙터에서 atlas만 1024로 줄이고 Clear → 거의 안 줄음.
     원인: 용량은 atlas 텍스처 크기 지배. 1024로 안 바뀌고 4096 유지된 경우도 있었음.
  ③ atlas 1024로 강제 + 글리프 수천 개 → World 텍스트 심하게 깨짐(블러).
     원인: 글자 多 × 작은 atlas = 글자당 픽셀 극소. 화질↔용량은 atlas 축소로 동시 해결 불가.

────────────────────────────────────────────────────────────────
[핵심 정리 — 기억할 것]
────────────────────────────────────────────────────────────────
  - 런타임 생성 글리프(닉네임·한마디 등 임의 한글)는 커밋되는 .asset에 안 쌓인다.
    → 전시 중 어떤 한글이 떠도 저장소 파일은 안 커짐. 에디터에서 본 고정 문구만 구워짐.
  - Static 전환은 금지(임의 한글 못 다룸 + Clear와 겹치면 □). Dynamic 유지가 정답.
  - 모드 전환·atlas 변경이 인스펙터에서 안 먹으면 Font Asset Creator로 재생성.
  - 화질은 Sampling Point Size가 좌우(atlas 크기 아님). 작은 atlas+많은 글자=블러.
  - 진짜 무손실 해법(선명+많은 한글+가벼운 저장소)은 Git LFS. (이번엔 미적용)

────────────────────────────────────────────────────────────────
[최종 처리]
────────────────────────────────────────────────────────────────
  - 미사용 5종 삭제: ExtraLight/Light/Medium/Regular/Thin (SDF+OTF).
    참조 0 확인(씬·프리팹·머티리얼·fallback·TMP Settings·ProjectSettings 전수). ~190MB↓
  - 사용 3종(ExtraBold/Bold/SemiBold): Atlas Population Mode=Dynamic 유지 +
    atlas 4096→2048 축소 + Clear Dynamic Data 재생성.

[추가 작업] 대기화면 영상 + 텍스트/영상 페이드 + Mock 시뮬 대기시간

주제: 대기화면에 영상을 넣고, 세션 준비 전엔 영상, 준비되면 영상 끄고 입장 버튼만
      나오도록 구성. Mock에서는 준비시간을 인스펙터로 시뮬레이션.

────────────────────────────────────────────────────────────────
[영상 게이트 구성 (WaitingScreenUI)]
────────────────────────────────────────────────────────────────
  - 영상 표시: VideoPlayer → RenderTexture(WaitingVideo_RT) → RawImage(VideoRoot).
    Source=Video Clip(mp4), Render Mode=Render Texture, Play On Awake·Loop.
  - 준비 전: 영상 + 대기 텍스트(_waitingText). 준비되면 영상 페이드 아웃 + 대기 텍스트 OFF,
    준비 텍스트(_readyText) + 입장 버튼 ON.
  - 대기/준비 텍스트를 별도 GameObject로 분리(내용·위치·스타일 독립).
  - 페이드: 영상 페이드 아웃(_videoFadeDuration), 대기 텍스트 페이드 인(_waitingTextFadeDuration).
    CanvasGroup 자동 추가, 공용 FadeCanvasGroup 재사용.

────────────────────────────────────────────────────────────────
[Mock 시뮬레이션 대기시간]
────────────────────────────────────────────────────────────────
  - _mockPrepSeconds(인스펙터): Mock은 세션이 즉시 준비되므로, 이 시간만큼 영상을 더 보여준 뒤
    입장 노출 → 실제 전시(Server)의 "준비 대기" 체감을 테스트.
  - Server는 무시(실제 ShowEnterButton 시점에 즉시 노출). SessionManager.dataSourceMode로 분기.

────────────────────────────────────────────────────────────────
[후속 조정]
────────────────────────────────────────────────────────────────
  - 텍스트 제거: _waitingText·_readyText는 null 허용이라 인스펙터 연결만 비우면 됨(코드 변경 X).
    → 텍스트 없이 "영상 → 입장 버튼"만으로 운용 가능.
  - 입장 버튼 지연 노출: _enterButtonDelay(인스펙터) 추가. 준비 완료(영상 페이드 시작) 후
    이 시간만큼 늦게 버튼이 나타남(영상이 사라진 뒤 자연스럽게 등장). 0이면 즉시.

────────────────────────────────────────────────────────────────
[트러블슈팅]
────────────────────────────────────────────────────────────────
  - 영상 화질 깨짐 → RenderTexture Size를 영상 해상도(예 1920×1080)로, Video Clip Transcode OFF.
  - 대기 텍스트 페이드가 안 보임 → 원인은 "씬 로드 직후 첫 프레임 unscaledDeltaTime이 수 초로
    튀어 페이드가 1프레임에 완료". FadeCanvasGroup에서 프레임당 진행량을 MaxStep(0.05s)로
    clamp해 해결(영상·Root 페이드에도 동일 적용). 디버그 로그로 원인 확인 후 로그 제거.
  - 텍스트 가독성(영상 위) → TMP는 UI Shadow/Outline 컴포넌트 미적용. 머티리얼 프리셋의
    Underlay(그림자)/Outline 또는 반투명 배경판 사용. ExtraBold SDF.mat 프리셋 추가.
