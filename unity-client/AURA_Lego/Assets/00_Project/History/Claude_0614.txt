  - 가이드가 처음 등장할 때 걷는 동작이 누락되지 않게.
  - 앞으로 Walk 를 바꿀 때 애니메이션이 누락되지 않도록 모션 라이브러리를 참조.

[세션 3] 가이드 등장 걷기를 모션 라이브러리 단일 소스로 전환 (누락 방지)
────────────────────────────────────────────────────────────────

## 핵심 문제
  가이드 등장/이동 걷기는 CharacterAnimationController.animation_walk() 가
  Animator Controller 의 "Walk" 상태를 재생하는데, 그 Walk 상태가
  Walk.anim(guid edbb6048…)을 "파일째 직접 참조" 하고 있었음.
  → Walk.anim 을 그냥 삭제하면 가이드 등장 걷기가 missing clip 으로 끊김.

## 조사
  Walk.anim(edbb6048…) 참조처 = NPC_AnimatorController.controller 의 Walk 상태 단 1곳
  (프로젝트 전역 grep 으로 확인).

## 설계 — 라이브러리를 단일 소스로
  Animator 의 Walk .anim 직접 참조에 의존하지 않고, 런타임에 모션 라이브러리
  (MotionType.Walk)의 클립으로 Walk 슬롯을 덮어쓴다.
  → 앞으로 Walk 를 바꿀 땐 NPC_MotionLibrary.asset 의 Walk(=12) Clip 만 교체하면
    가이드 등장 걷기·프롬프트 걷기 둘 다 따라온다. 파일이 사라져도(라이브러리에
    Walk 만 있으면) 등장 걷기가 누락되지 않는다.

## 수정 파일 1: Scripts/Character/CharacterAnimationController.cs
  - ApplyWalkFromLibrary(MixamoMotionLibrary library) 추가
      · AnimatorOverrideController 에서 이름이 "Walk" 로 시작하는 슬롯(예: Walk2)을
        찾아 라이브러리 Walk 클립으로 덮어씀(GetOverrides → ApplyOverrides).
      · 라이브러리에 Walk 가 없으면(HasClip false) 아무것도 안 함 →
        Animator 의 기본 Walk 클립(폴백)이 그대로 사용됨.
      · _overrideController 가 아직 없으면 InitOverrideController() 로 보강.
      · "Walk*" 접두어 매칭이라 base 가 Walk2/Walk3/Walk5 등 무엇이든 동작.

## 수정 파일 2: Scripts/Character/GeneratedCharacterSpawner.cs
  - SetupAsGuide(): 가이드 초기화 직후 anim.ApplyWalkFromLibrary(motionLibrary) 호출.

## 수정 파일 3(에셋): Animations/Character/NPC_AnimatorController.controller
  - Walk 상태 base 클립 repoint: Walk.anim(edbb6048…) → Walk2.anim(e97d14b3…)
    → base 참조도 안 끊기게 + 라이브러리 미연결 시 폴백 클립 역할.

## 삭제: Animations/Mixamo/Walk.anim (+ .meta)
  - 참조처 0건 확인 후 삭제(Animator 는 Walk2, 라이브러리는 Walk2/Walk3).
  - 삭제 후 edbb6048 전역 grep = 0건(잔존 참조 없음).

## 데이터 흐름
  [가이드 등장] animation_walk() → Animator "Walk" 상태
    → (런타임 override) 라이브러리 MotionType.Walk 클립(= Walk2) 재생
  [프롬프트]  "걸어줘"/"산책" → MotionType.Walk → GetRandomClip(직전 제외)
    → Walk2/Walk3 변형 번갈아 재생

[세션 4] (진단) EventSystem NaN 경고 — 코드 변경 없음
────────────────────────────────────────────────────────────────

## 증상
  Screen position out of view frustum (screen pos -nan(ind), -nan(ind))
  (Camera rect 0 0 1920 1080)
  UnityEngine.EventSystems.EventSystem:Update ()

## 의미
  EventSystem 이 매 프레임 GraphicRaycaster 가 붙은 Canvas 에 포인터를 투영하는데,
  그 Canvas 의 카메라 투영이 NaN 으로 계산될 때 발생. 0610 Bug4(PlazaSessionView
  edge-on) 와 같은 계열. 이번 Walk 작업/애니메이션과는 무관(씬 Canvas 설정 문제).

## 코드 점검 결과 (무죄)
  DialogueUI / NPCSpeechBubble / PlazaSessionView 의 빌보드는 모두
  transform.forward = cam.forward 로 안전하고 cam null 도 가드함(edge-on 방지).

## 가능성 높은 원인 (씬 설정, 가능성 순)
  1) Screen Space - Camera 캔버스인데 Render Camera 가 비어있음/비활성 카메라
     (0610 VR→키마 전환·신규 WaitingScreen 가능성) → Overlay 로 바꾸거나
     활성 Main Camera 를 Render Camera 에 연결.
  2) World Space 캔버스 + GraphicRaycaster 인데 빌보드 없음/scale 0/edge-on
     (후보: OwnCreationInteractPanel, MapTeleportUI 가 World Space 인 경우)
     → 표시 전용이면 GraphicRaycaster 제거, 클릭 필요하면 빌보드 적용.
  3) Camera.main 이 null 이라 worldCamera 미설정(MainCamera 태그 누락 등).

## 범인 찾기
  Console > Error Pause 켜고 Play / 의심 캔버스의 GraphicRaycaster 를 하나씩 끄며
  확인 / Render Mode·Render(Event) Camera·Scale 점검.

## 상태
  미해결(씬 수정 필요). 어느 캔버스인지 확인되면 후속 처리.

[세션 5] 설계 — 회피 주체/책임 분리
────────────────────────────────────────────────────────────────

## NavMesh 채택 근거
  com.unity.ai.navigation 2.0.12 + modules.ai 설치 확인 → NavMeshAgent 기반 회피.
  스티어링(레이캐스트)보다 건물·오브제 회피가 견고하고 확장성 좋음.

## 회피 책임 (사용자 확인: "오브제도 피하게")
  - 건물 등 정적 지형: 씬 NavMesh 베이크로 non-walkable → 자동 회피
  - 이전 창작물 오브제(런타임 스폰): NavMeshObstacle(carve)로 표시 → 캐릭터가 우회
    (오브제는 움직이지 않음 — "객체가 회피"가 아니라 "캐릭터가 객체를 회피")
  - 캐릭터끼리: NavMeshAgent 자동 회피

## 분리 설계 (기존 동작 보존 + 저결합)
  - 시그니처-온-어프로치 트리거를 '투표 뷰(LikeSystem)'에서 '캐릭터'로 이관.
    구현은 LikeSystem 무수정 — 이전 창작물은 view.SetCharacter 를 호출하지 않음
    → 뷰 트리거의 PlaySignatureMotion 이 캐릭터 미연결로 자연 no-op(투표만 동작).
    내 창작물(AttachViewToCurrentSession)은 SetCharacter 유지 → 기존 동작 그대로.
