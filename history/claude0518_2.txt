프로젝트명: Lego-Digital-Twin / MINIVERSE

현재 프론트엔드와 백엔드의 기본 테스트는 완료된 상태다.
따라서 이번 작업에서는 전체 구조를 새로 만들거나 대규모 리팩토링하지 말고, 기존 구현을 최대한 유지하면서 “전시 기획 수정사항”과 “UI/UX 수정사항”만 반영해줘.

중요:
- 기존 프론트엔드/백엔드 구조를 임의로 갈아엎지 말 것
- 이미 동작하는 API 흐름은 최대한 유지할 것
- 필요한 경우에만 asset_type, 화면 흐름, 문구, UI 애니메이션, 상태 표시를 수정할 것
- 기존 테스트가 깨지지 않도록 작은 단위로 수정할 것
- 수정 전 현재 파일 구조와 관련 코드를 먼저 확인한 뒤 작업할 것

==================================================
1. 전시 기획 수정사항
==================================================

기존 기획에서는 캐릭터, 건축물, 자동차를 촬영하고 3D 변환하는 흐름이 있었지만, 이번 전시 버전에서는 범위를 줄인다.

수정 후 전시 대상:
1. 캐릭터
2. 오브제

삭제/제외할 대상:
- 집
- 건축물
- 자동차
- vehicle
- building
- car 관련 화면/문구/흐름

단, 기존 코드에 building/vehicle 관련 코드가 남아 있더라도 이번 UI 흐름에서 사용하지 않도록 처리하면 된다.
무리하게 모든 코드를 삭제하지 말고, 현재 테스트가 깨지지 않는 선에서 화면 흐름과 API 호출 대상만 character/object 중심으로 수정해줘.

최종 asset_type:
- character
- object

처리 방식:
- character: 3D 변환 + 애니메이션 적용 대상
- object: 3D 변환만 수행하는 정적 오브제

즉:
- 캐릭터는 NPC가 될 대상
- 오브제는 Unity 월드에 배치될 정적 3D 모델

==================================================
2. UI/UX 전체 흐름 수정사항
==================================================

태블릿 UI 흐름은 아래 순서로 변경한다.

[0] 시작 로고 화면
- MINIVERSE 로고 애니메이션 출력
- 애니메이션이 끝난 후 시작하기 화면으로 이동

[1] 첫 화면
- 커다란 “시작하기” 버튼
- 버튼 클릭 시 session 발급
- 기존 POST /sessions API 사용
- session_id 저장

[2] 안내 문구 화면
문구:
“안녕하세요!”

[3] 안내 문구 화면
문구:
“MINIVERSE 레고 세상에 오신걸 환영해요!”

[4] 안내 문구 화면
문구:
“먼저 여러분의 NPC가 될 캐릭터를 촬영할게요!”

[5] 안내 문구 화면
문구:
“캐릭터를 앞에 표시된 곳에 올려주세요!”

[6] 안내 문구 화면
문구:
“캐릭터 촬영을 시작합니다”

[7] 캐릭터 촬영 화면
- 카메라 미리보기 영역
- 동그란 촬영 버튼
- 촬영 버튼을 누르면 캐릭터 촬영 완료
- 기존 asset 업로드 API 사용
- asset_type = character

[8] 안내 문구 화면
문구:
“이제 당신이 조립한 오브제를 촬영할게요!”

[9] 안내 문구 화면
문구:
“오브제를 앞에 표시된 곳에 올려주세요!”

[10] 안내 문구 화면
문구:
“오브제 촬영을 시작합니다”

[11] 오브제 촬영 화면
- 카메라 미리보기 영역
- 동그란 촬영 버튼
- 촬영 버튼을 누르면 오브제 촬영 완료
- 기존 asset 업로드 API 사용
- asset_type = object

중요:
- 캐릭터와 오브제 촬영이 모두 완료되면 기존 Worker/백엔드 흐름에 따라 백그라운드 처리가 시작되도록 유지
- character 작업은 3D 생성 + 애니메이션 적용
- object 작업은 3D 생성만 수행

[12] 캐릭터 이름 입력 화면
문구:
“캐릭터 NPC의 이름을 지어주세요!”

기능:
- 이름 입력 필드
- 입력한 이름은 character_npc_name으로 저장
- 이 이름은 Unity에서 캐릭터 NPC 이름으로 사용됨

[13] 오브제 이름 입력 화면
문구:
“오브제의 이름을 지어주세요!”

기능:
- 이름 입력 필드
- 입력한 이름은 object_name으로 저장
- 이 이름은 Unity에서 오브제 이름/라벨로 사용됨

이름 입력 완료 후 기존 profile/session update API를 사용해서 저장한다.
가능하면 기존 profile API를 유지하되, 필요한 필드만 추가해줘.

요청 데이터 예시:
{
  "character_npc_name": "몽글이",
  "object_name": "하늘탑"
}

기존 nickname 필드가 이미 사용 중이라면 다음 중 더 안전한 방식으로 처리해줘.
- character_npc_name을 nickname에 매핑
- 또는 character_npc_name 필드를 별도로 추가
- 단, 기존 테스트와 API가 깨지지 않도록 구현

[14] 로딩 화면
문구:
“(캐릭터이름)과 (오브제이름)이 3D로 변환 중입니다!”

예시:
“몽글이와 하늘탑이 3D로 변환 중입니다!”

로딩 UI 요구사항:
- 기존 status polling 또는 상태 조회 로직 유지
- GET /sessions/{session_id}/status 사용
- ready_for_unity === true가 되면 완료 화면으로 이동
- 캐릭터/object 각각의 상태를 반영 가능하면 좋음

상태별 문구 예시:
- queued: “디지털 변환을 준비하고 있어요”
- generating: “레고 모형을 3D 모델로 만들고 있어요”
- animating: “캐릭터에 움직임을 부여하고 있어요”
- downloading: “MINIVERSE 월드로 이동 중이에요”
- completed: “준비가 완료되었어요”

[15] 완료 화면
문구:
“완료되었습니다! 이제 VR World로 이동할게요!”

기능:
- 완료 메시지 표시
- 필요하면 운영자/관객이 다음 단계로 넘어갈 수 있는 버튼 유지

==================================================
3. 시작 로고 화면 애니메이션
==================================================

첨부한 MINIVERSE 로고 이미지를 참고해서 시작 로고 화면을 수정해줘.

원하는 디자인:
- 배경은 흰색
- 중앙에 MINIVERSE 로고
- 텍스트는 보라색~하늘색 계열 그라데이션 느낌
- 오른쪽 상단에 레고 블록 모양 아이콘

원하는 애니메이션:
1. “MINIVERSE” 글자가 fade in 되며 점점 선명해짐
2. 동시에 살짝 scale up 되며 등장
3. 글자가 다 등장하면 젤리처럼 출렁이는 애니메이션
4. 이후 오른쪽 상단 레고 블록이 위에서 떨어짐
5. 블록이 마지막 글자 E 근처에 부딪히는 느낌으로 떨어짐
6. 공처럼 3번 정도 튀는 bounce 애니메이션
7. 최종적으로 첨부 이미지와 유사한 위치에 안착

구현 방향:
- 가능하면 텍스트와 레고 블록을 분리해서 애니메이션
- 전체 로고 이미지 한 장만 사용할 경우 블록 낙하 애니메이션이 어려우므로, 더 나은 방법을 제안하고 적용
- 추천 방식:
  - MINIVERSE 텍스트는 React/CSS 또는 SVG로 렌더링
  - 레고 블록은 별도 이미지/SVG로 사용
  - Framer Motion 또는 기존 애니메이션 라이브러리 사용
- 이미 Framer Motion이 프로젝트에 없다면, 설치 여부를 확인하고 필요 시 추가 제안
- 기존 프로젝트 스타일에 맞게 적용

==================================================
4. 전체 UI 스타일 수정사항
==================================================

전체 UI 스타일은 다음 방향으로 맞춰줘.

스타일 키워드:
- Toss-inspired modern minimal UI
- 흰색 배경
- 넓은 여백
- 큰 타이포그래피
- 검정/짙은 회색 텍스트
- 파란색 또는 민트 계열 포인트 컬러
- 둥근 버튼
- 부드러운 그림자
- 모바일/태블릿 최적화
- fade transition
- wave text animation
- 부드러운 micro interaction

각 화면의 문구는:
- fade in / fade out
- 부드럽게 순차적으로 등장하는 wave animation 느낌
- 화면 전환은 자연스럽게

==================================================
5. 이미지 파일 배치 가이드 요청
==================================================

아주 중요:
첨부한 MINIVERSE 로고 이미지 또는 분리된 로고 이미지 파일을 코드 에디터에서 어디에 넣어야 하는지 구체적으로 알려줘.

반드시 답변에 포함해줘:
1. 첨부한 로고 이미지를 그대로 사용할 경우 어디에 넣어야 하는지
2. 텍스트와 블록을 분리해서 사용할 경우 각각 어디에 넣어야 하는지
3. 이미지 1장 사용 방식의 한계
4. SVG/CSS 텍스트 + 블록 이미지 방식의 장점
5. 내가 직접 추가해야 할 파일 목록

예시 경로:
- public/images/miniverse-logo.png
- src/assets/logo/miniverse-block.png
- src/assets/logo/miniverse-text.svg

내가 원하는 애니메이션은 텍스트와 블록이 따로 움직여야 하므로, 가능하면 분리 asset 방식을 권장하는지 검토해줘.

==================================================
6. 기존 API/백엔드 수정 방향
==================================================

이미 프론트엔드와 백엔드 테스트는 완료된 상태이므로, 이번에는 최소 수정으로 진행해줘.

필요한 API 흐름:
- POST /sessions
- POST /sessions/{session_id}/assets
  - asset_type = character
  - asset_type = object
- PATCH /sessions/{session_id}/profile
  - character_npc_name
  - object_name
- GET /sessions/{session_id}/status

수정 포인트:
- 기존 building/vehicle/car 흐름이 있다면 이번 전시 UI에서는 제외
- asset_type object를 지원하지 않는다면 추가
- 기존 building을 object로 대체하는 것이 더 안전하면 그렇게 제안 후 적용
- ready_for_unity 판단은 character와 object 두 asset이 모두 completed 되었을 때 true가 되도록 수정
- character는 animating stage가 있을 수 있음
- object는 generating/downloading/completed 중심이면 됨

==================================================
7. 상태 관리 수정사항
==================================================

프론트엔드 상태는 다음을 중심으로 정리해줘.

필요 상태:
- currentStep
- sessionId
- characterImage
- objectImage
- characterAssetId
- objectAssetId
- characterNpcName
- objectName
- loadingStatus
- readyForUnity
- error

기존 상태 관리 구조가 있다면 최대한 유지하고, 필요한 필드만 추가해줘.

==================================================
8. 작업 방식
==================================================

아래 순서로 작업해줘.

1. 현재 프로젝트의 프론트엔드/백엔드 구조를 먼저 확인
2. 기존 구현 중 character/building/vehicle 관련 흐름이 어떻게 되어 있는지 파악
3. 이번 전시 버전에 맞춰 character/object 흐름으로 최소 수정 계획 제안
4. 이미지 파일 배치 가이드 제안
5. UI step 흐름 수정
6. 시작 로고 애니메이션 추가
7. 촬영 흐름에서 character/object 업로드로 수정
8. 이름 입력 화면 추가/수정
9. 로딩 화면 문구와 status polling 수정
10. ready_for_unity 판단 기준 수정
11. 간단한 테스트 방법 안내

==================================================
9. 주의사항
==================================================

- 전체 프로젝트 구조를 임의로 갈아엎지 말 것
- 이미 테스트 완료된 프론트엔드/백엔드 흐름을 깨지 말 것
- building/vehicle 코드를 무조건 삭제하지 말고, 이번 UI에서 사용하지 않도록 처리하는 것을 우선 고려
- API 이름이 기존과 다르면 기존 구조에 맞춰 최소 수정
- 촬영 기능이 이미 구현되어 있다면 기존 camera/capture 코드를 재사용
- 실제 API 서버 주소와 환경변수 구조는 기존 것을 유지
- 불확실한 부분은 TODO 주석으로 남길 것
- 작업 후 어떤 파일을 수정했는지 요약해줄 것

==================================================
10. 최종 목표
==================================================

이번 작업의 최종 목표는 다음이다.

1. 전시 대상이 캐릭터 + 오브제 2개로 정리됨
2. 자동차/집/건축물 흐름은 이번 전시 UI에서 제거됨
3. 캐릭터는 3D 변환 + 애니메이션 적용 대상으로 처리됨
4. 오브제는 3D 변환만 수행됨
5. 태블릿 UI가 새 UX 흐름으로 동작함
6. MINIVERSE 시작 로고 애니메이션이 적용됨
7. 캐릭터 이름과 오브제 이름을 입력받음
8. 로딩 화면에서 “캐릭터이름과 오브제이름이 3D로 변환 중입니다!” 문구 표시
9. character와 object가 모두 완료되면 VR World 이동 완료 화면 표시

위 요구사항은 기존 프론트엔드/백엔드 테스트가 완료된 상태에서의 수정 요청이다.
새 프로젝트를 만들지 말고, 현재 코드를 읽고 최소 수정으로 반영해줘.
먼저 수정 계획과 이미지 파일 배치 가이드를 설명한 뒤, 내가 승인하면 실제 코드를 수정해줘.
