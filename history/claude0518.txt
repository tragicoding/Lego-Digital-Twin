━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

  1. Worker 순차 처리
     현재 RQ Worker 1개가 캐릭터(~3분) → 건물(~1분) → 자동차(~1분) 순서로 처리
     전체 완료까지 약 5~6분 소요
     병렬화하려면 Worker 여러 개 띄우거나 gevent/eventlet 사용

  2. Worker 프로세스 크래시 주의
     이전 Task가 오류로 죽으면 Worker가 멈추는 경우 있음
     증상: 모든 에셋이 'waiting' 상태로 멈춤
     해결: pkill -f run_worker && conda run -n triposr python run_worker.py

  3. Tripo API 유효 animation preset (검증 완료)
     walk ✅  idle ✅  run ✅  jump ✅
     wave ❌  hello ❌  dance ❌  (error_code 1004)

  4. Tripo animate_retarget output 키
     image_to_model: result["output"]["pbr_model"]
     animate_retarget: result["output"]["model"] 또는 다른 키
     → tripo_service.py download_glb에서 다중 키 시도하도록 수정됨

  5. .env 파일 위치
     apps/backend/.env  (git 제외)
     TRIPO_API_KEY, DATABASE_URL, REDIS_URL 필요

  6. Redis FLUSHDB 주의
     docker exec lego_redis redis-cli FLUSHDB 하면
     Queue의 미처리 잡도 전부 삭제됨
