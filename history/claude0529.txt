## 1. 프로젝트 개요

**MINIVERSE** — LEGO 피규어 사진 촬영 → Tripo3D API 3D 변환 → Unity VR 월드 전시 시스템.

전시 흐름:
1. 태블릿 앱(React)에서 LEGO 피규어 4방향 촬영 + 오브제 촬영
2. FastAPI 백엔드가 이미지 수신 → Redis/RQ Worker로 Tripo3D API 호출
3. Tripo가 3D 모델(FBX + GLB) 생성
4. Unity VR 월드에서 런타임으로 FBX/GLB 로드 → 유저 캐릭터/오브제로 스폰

## 4. 현재 개발 완료 상태 (2026-05-29 기준)

### 4-1. 캐릭터 촬영 4방향 지원 — 완료

**목적**: 기존 front 1장 → Tripo API에 4방향(front/left/back/right) 전달해 더 정밀한 3D 모델 생성

**Frontend `CapturePage.tsx`** 촬영 스텝 순서:
```
가이드 → 캐릭터 정면(front) → 가이드 → 캐릭터 좌측면(left) → 가이드
→ 캐릭터 후면(back) → 가이드 → 캐릭터 우측면(right) → 가이드 → 오브제
```

촬영 스텝 타입:
```typescript
interface CaptureStep {
  type: "capture";
  assetType: "character" | "object";
  label: string;
  emoji: string;
  view?: "front" | "back" | "left" | "right";
}
```

**업로드 로직 핵심**:
- `view="front"`: DB에 Asset 생성 + Redis Queue 등록 → Worker가 파이프라인 시작
- `view="left"/"back"/"right"`: 파일만 저장 (`character_{view}_{filename}`) → DB/Queue 없음
- Worker가 90초 동안 `character_left_*`, `character_back_*`, `character_right_*` 파일 대기

### 4-2. Backend `assets.py` 라우터 — 완료

```python
view: Literal["front", "back", "left", "right"] = Form("front")

if view in ("back", "left", "right") and asset_type == "character":
    save_path = save_dir / f"character_{view}_{file.filename}"
    # 파일 저장만, 큐 미등록
    return AssetUploadResponse(asset_id="", status="saved", asset_type=f"character_{view}")
```

### 4-3. `tripo_service.py` — 완료

주요 함수:
```python
upload_image(image_path)           → file_token
create_model_task(token, path)     → task_id  (image_to_model, 단일 이미지 fallback)
create_multiview_task(front, back, left=None, right=None) → task_id
    # 없는 방향은 front token으로 패딩 (API가 정확히 4장 필요)
    # Tripo multiview_to_model: [front, left, back, right] 4장 필수
    # 2장/3장이면 error 1004 반환 → front로 패딩해서 해결
create_rig_task(model_task_id, out_format="fbx") → task_id
poll_task(task_id, interval=1.0, timeout=600.0)  → result dict
download_glb(result, output_path)  → Path  (pbr_model URL)
download_fbx(result, output_path)  → Path  (animate_rig model URL)
```

### 4-4. `character_task.py` 파이프라인 — 완료

```
front 업로드 → Worker 시작
    ↓
front 이미지 Tripo 업로드 (file_token)
    ↓
최대 90초 대기: character_left_*, character_back_*, character_right_* 파일 감지
    ↓
back 있으면: multiview_to_model (front/left/back/right, 없는 방향은 front 패딩)
back 없으면: image_to_model (fallback)
    ↓
poll 완료 대기
    ↓
texture.glb 다운로드 (pbr_model — PBR 텍스쳐 소스, Unity glTFast용)
    ↓
animate_rig (out_format="fbx")
    ↓
poll 완료 대기
    ↓
rigged.fbx 다운로드 (Unity Animator 리타겟팅용)
    ↓
DB 업데이트: model_url=FBX URL, thumbnail_url=GLB URL, status="completed"
```

저장 파일:
- `npc_{n}_texture.glb` — PBR 텍스쳐 GLB
- `npc_{n}_rigged.fbx` — 리깅된 FBX (뼈대 포함, 텍스쳐 없음)

### 4-5. `object_task.py` 파이프라인 — 완료 (변경 없음)

```
object 이미지 → image_to_model → object_{n}.glb 다운로드
```

### 5-2. SQLAlchemy 모델 등록

`apps/backend/main.py`에 반드시 아래 import가 있어야 관계(relationship) 해석 오류 없음:
```python
from .models import Session, Asset, AssetAnimation, PlazaObject  # noqa: F401
```

### 5-3. Tripo multiview_to_model 4장 필수

Tripo API `multiview_to_model`은 정확히 4장 `[front, left, back, right]` 필요. 2장/3장 → error 1004. 없는 방향은 front token으로 패딩하여 해결.

### 5-4. worker가 back 이미지를 못 찾는 경우

front 업로드 → Worker 즉시 실행 시작 → 90초 동안 polling.
사용자가 front 업로드 후 90초 안에 left/back/right를 모두 업로드해야 함.
90초 초과 시 back_path=None → image_to_model fallback.
