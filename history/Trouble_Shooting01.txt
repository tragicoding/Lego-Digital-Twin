# [1] feature/unity → test_app 교체 후 파일 누락

## Problem
이전 세션에서 `git checkout origin/feature/unity -- unity-client/` 로
unity-client 폴더를 교체한 뒤 커밋했으나, GitHub test_app 브랜치에
feature/unity에 있던 파일 다수가 누락됨.

누락 유형:
  - Scripts 하위 .meta 파일 19개 (CharacterAnimationController.cs.meta 등)
  - External Assets FBX / .anim / .controller 파일
    (elsa.fbx, hermione.fbx, ron.fbx, HarryHouse.fbx, Hogwarts Castle.fbx 등)
  - Prefabs/HarryTerrain.prefab
  - StreamingAssets/Config/server_config.json.meta
  - History/0524_Claude.txt

## Error Message
(Unity Editor에서 발생)
  "Missing Script" — 씬/프리팹의 스크립트 참조 깨짐
  .meta 파일이 없으면 Unity가 새 GUID를 생성하여 기존 씬 참조가 무효화됨

## Cause
CLAUDE.md RULE-03 ("git add . 금지, 파일 명시적 지정") 원칙을 따르면서
브랜치 교체 후 수백 개 파일을 수동으로 스테이징하는 과정에서
.meta 파일과 바이너리 에셋이 누락됨.

`git checkout origin/feature/unity -- unity-client/` 는 정상 실행됐으나
이후 git add 단계에서 새로 추가된 .cs 파일 위주로만 지정하다가 발생.

## Solution
1. 누락 파일 목록 확인:
   git diff --name-status origin/feature/unity -- unity-client/ | grep "^D"

2. 누락 파일 일괄 복원 (Logs, 의도적 제외 파일 제외):
   git diff --name-only origin/feature/unity -- unity-client/ | \
     grep "^unity-client/" | \
     while IFS= read -r f; do
       status=$(git diff --name-status origin/feature/unity -- "$f" | cut -f1)
       [ "$status" = "D" ] && echo "$f"
     done | grep -v "Logs/" | grep -v "VRIntroGuide" | \
     while IFS= read -r f; do
       git checkout origin/feature/unity -- "$f"
     done

3. 디렉토리 단위로 스테이징:
   git add unity-client/
   git commit -m "fix(unity): feature/unity 누락 파일 복원"

## Prevention
git.md 에 RULE-08 추가:
  브랜치 폴더 교체 시 올바른 순서:
  1. git checkout origin/<브랜치> -- <경로>/
  2. git diff --name-status origin/<브랜치> -- <경로>/   ← 누락 확인
  3. git add <경로>/                                     ← 디렉토리 단위 허용
  4. git diff --name-status --cached origin/<브랜치> -- <경로>/  ← D 없는지 최종 검증
  5. git commit

  Unity: .meta 파일 누락 시 씬/프리팹 GUID 참조 전부 깨짐

## Related Files / Commands
  git diff --name-status origin/<브랜치> -- <경로>/
  git.md → RULE-08 추가, AGENT-GIT-10 추가

## Notes
  - VRIntroGuide.cs 는 GuideNPCController.cs 로 대체됐으므로 복원 제외
  - 총 49개 파일 복원 (FBX 3개, anim 파일들, .meta 19개, prefab 등)

# [2] CharacterTextureApplier — FBX 텍스쳐 자동 적용

## Problem
GeneratedCharacters/**/character/ 폴더에 *_rigged.fbx + *_texture.glb 쌍을
넣었을 때 FBX에 텍스쳐가 없어 Unity에서 캐릭터가 회색으로 표시됨.

## Error Message
  (Inspector에서) Material이 None 또는 회색 Default Material 상태

## Cause
Tripo3D API animate_rig(out_format="fbx") 결과물인 FBX에는 텍스쳐가 없음.
텍스쳐는 image_to_model 단계의 pbr_model GLB에만 존재.
GLB에서 FBX로 텍스쳐를 연결하는 작업이 자동화되어 있지 않았음.

## Solution
Unity Editor 스크립트 작성:
  Assets/00_Project/Editor/CharacterTextureApplier.cs

  처리 흐름:
  1. AssetPostprocessor.OnPostprocessAllAssets → *_rigged.fbx / *_texture.glb 감지
  2. EditorApplication.delayCall → 현재 임포트 사이클 종료 후 실행
  3. AssetDatabase.LoadAllAssetsAtPath(glbPath) → GLB sub-asset 로드
     - Material 프로퍼티에서 Texture2D 추출 (_BaseMap, _BumpMap, _MetallicGlossMap)
     - fallback: 이름 키워드로 탐색 (basecolor, normal, metallic 등)
  4. Materials/npc_N.mat 생성 (URP Lit 셰이더)
  5. ModelImporter.materialLocation = External
  6. FBX embedded Material → 위 .mat 으로 AddRemap
  7. importer.SaveAndReimport()

  재귀 방지: static bool _isApplying 플래그

  수동 실행: Tools > MINIVERSE > Apply Character Textures

## Prevention
  - glTFast 6.x (com.unity.cloud.gltfast 6.18.0) 설치 필수
  - GLB가 먼저 Unity에 임포트된 상태여야 sub-asset 접근 가능
  - FBX 내부 Material 이름 불명확 시 기본값 "Material" 로 리맵

## Related Files / Commands
  Assets/00_Project/Editor/CharacterTextureApplier.cs (신규)
  Assets/00_Project/Scripts/Character/CharacterAnimationController.cs (TODO 정리)
  Assets/00_Project/GeneratedCharacters/mocking/character/README.md

## Notes
  Server Mode 텍스쳐 적용은 별도:
    glTFast async Load → GetMaterial(0) → SkinnedMeshRenderer.material 교체
    CharacterAnimationController.cs 내 TODO 주석 참고

# [3] FBX Binary 파싱 — 외부 라이브러리 없이 리깅 정보 추출

## Problem
npc_3_rigged.fbx 리깅 구조 파악이 필요했으나
triposr conda 환경에 FBX SDK / pyassimp 등 3D 파싱 라이브러리 미설치.

## Error Message
  ModuleNotFoundError: No module named 'fbx'
  ModuleNotFoundError: No module named 'pyassimp'

## Cause
triposr 환경은 FastAPI 백엔드 전용으로 구성되어 있어 3D 패키지 없음.

## Solution
FBX 7.4 Binary 포맷을 Python struct + zlib 만으로 직접 파싱.

FBX Binary 7.4 구조:
  Header: b"Kaydara FBX Binary  \x00\x1a\x00" + version(u32, 27번째 바이트)
  Node: end_offset(u32) + num_props(u32) + props_byte_len(u32)
        + name_len(u8) + name + properties + children (재귀)
  Property 타입:
    Y=u16, C=bool, I=i32, F=f32, D=f64, L=i64, S=string, R=raw
    f/d/l/i/b = 배열 (cnt + enc + clen + data, enc=1이면 zlib 압축)

추출 결과 (rigging.txt, 774줄):
  - 본 42개 계층 구조
  - Bind Pose 4×4 행렬 43개
  - TransformLink 행렬 (글로벌 T-Pose 위치)
  - Skin Cluster 41개 (영향 정점 수, 웨이트 min/max/avg)
  - Local Transform (Translation, Rotation, Scale, PreRotation)
  - 애니메이션 Stack 0개 확인 → 리깅 전용 FBX

## Prevention
  FBX 7.5+ 는 offset이 u64로 변경 (ver >= 7500 분기 처리 필수)
  배열 프로퍼티 enc 필드: 0=원본, 1=zlib 압축

## Related Files / Commands
  /rigging.txt (프로젝트 루트)
  python3 + struct + zlib (외부 패키지 불필요)
